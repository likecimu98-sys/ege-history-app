# Исходники Telegram-бота

Сняты с боевого сервера (`/root/bot/`) 27.07.2026. До этого дня исходников бота
в репозитории не было вообще — только патч `bot-vps.patch`, — то есть после
потери машины бота нечем было бы восстановить, а расхождение прода с
репозиторием заметить было невозможно. Ровно так уже разъехался
`server/api/src/auth.js` (см. журнал в AGENTS.md).

## ⚠️ Чего здесь нет и быть не должно

С сервера скопированы ТОЛЬКО исходники. Намеренно не перенесены:

| Что | Почему |
|---|---|
| `.env` | Токен бота, `INTERNAL_API_TOKEN`, `ADMIN_ID`. Секреты живут только на сервере. |
| `serviceAccount.json` | Ключ Firebase Admin. То же. |
| `users.db*` | Рабочая база бота с данными пользователей. |
| `node_modules/` | 88 МБ, ставится из `package-lock.json`. |
| `bot.js.bak*`, `engage.js.bak*` | Шесть накопившихся ручных бэкапов. История теперь в git. |
| `rollback-*/` | Снимок отката cutover, трогать нельзя. |

Перед коммитом файлы проверены на захардкоженные секреты: токенов и приватных
ключей нет, всё читается из `process.env`.

## Как запущен на бою

`pm2` под именем `hist-bot`, рабочий каталог `/root/bot`, конфигурация в
`.env` там же. Порт токен-эндпоинта — 8791.

⚠️ **`api.telegram.org` доступен с этого VPS ТОЛЬКО через запись в `/etc/hosts`**
(`149.154.167.220`). Без неё бот молча не отправляет сообщения — см. память
проекта. Не «чини» это удалением строки из hosts.

## Как выкатывать

Автоматического скрипта для бота пока НЕТ (в отличие от `deploy-api.ps1` и
`deploy-static.ps1`). Пока — вручную: скопировать изменённые файлы в
`/root/bot/`, затем `pm2 restart hist-bot`.

⚠️ Правишь бота на сервере — перенеси правку и сюда, иначе этот каталог
устареет и станет ловушкой для следующего деплоя.
